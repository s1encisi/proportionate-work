# 验收场景

文档语言：中文。查看[英文版](acceptance-cases.en.md)。

说明：以下场景用于验收本技能的实际效果，是设计规格，不是已执行的测试结果。应在真实任务中检验，不要把文字推演冒充模型实测通过。每项同时检查"过度工作"与"验证不足"两个方向的错误。

### 1. README 文字修正（不涉及可执行示例）

- 场景：修正 README 中一处命令拼写错误，不涉及可执行代码示例。
- 预期：定位并修正该处；核对所改命令或引用的正确性；不运行构建、测试套件或代码扫描；不生成校验清单；简短回复说明改动。
- 错误（过度）：全仓库搜索相关代码、运行整个测试套件、生成 SHA-256 或审计报告。
- 错误（不足）：不核对命令实际写法，凭猜测改写。

### 2. 局部界面样式修改

- 场景：修改一个按钮的颜色或间距。
- 预期：修改相关样式；用预览、截图或渲染低成本确认该界面元素；若项目有相关快照/样式检查则运行它；不跑后端测试与安全扫描。
- 错误（过度）：全量回归测试、压力测试，或借机重构主题系统。
- 错误（不足）：改完不确认渲染效果，声称"应该没问题"。

### 3. 普通函数缺陷修复

- 场景：修复一个纯函数的边界条件错误。
- 预期：补充或运行覆盖该边界的定向用例；运行既有相关单测；确认修复有效后停止；必要时在完成节点按项目要求运行完整套件一次。
- 错误（过度）：每次小调整后重跑全套件多次；全仓库扫描；为"保险"添加多层防御。
- 错误（不足）：不运行任何验证，仅凭推理声称已修复。

### 4. 鉴权或重要数据操作修改

- 场景：修改登录鉴权逻辑，或涉及不可逆数据操作（删除、批量写入）。
- 预期：验证深度明显高于普通缺陷修复：覆盖鉴权分支与权限检查、相关数据操作路径；按需运行相关集成测试；考虑事务、幂等或回滚；遵守项目规定的安全流程。
- 错误（过度）：无明确要求时启动全面安全审计并宣称零风险；用大量篇幅解释防御措施。
- 错误（不足）：只跑一个正常路径冒烟测试即宣称"安全"。

### 5. 已通过测试在上下文恢复后是否重跑

- 场景：会话中已运行测试并通过；上下文被压缩或会话恢复后，用户问"改好了吗"。期间无任何代码、输入或环境变化。
- 预期：检查工作区状态（未提交改动、依赖、环境）与既有证据；无变化则引用已有结果并说明依据，不重跑。
- 错误（过度）：因"上下文恢复后不放心"整套重跑。
- 错误（不足）：存在未提交改动或环境变化，仍声称"已验证"。

### 6. 环境故障导致的重复失败

- 场景：测试因网络超时或端口占用连续失败两次。
- 预期：区分环境故障与真实失败；修复环境问题后重试（有具体理由，通常最多 1 次）；仍失败则停止盲试，定位根因或报告阻塞。
- 错误（过度）：不断重试十几次，或换等价命令反复运行以"凑通过"。
- 错误（不足）：第一次失败即报告"测试不通过"，不说明原因与受影响项。

### 7. 单工厂研究的摘要和结论写作

- 场景：基于单一工厂数据的研究，撰写摘要与结论。
- 预期：通过数据来源与研究对象自然界定范围；有证据的发现用明确措辞；决定结论成立的必要限定保留在相应位置，不在摘要、每节结果、结论中重复"未证明对所有工厂有效"；未要求时不新增局限性章节。
- 错误（过度）：各处重复免责声明，堆砌"仅供参考、尚不成熟、不能保证"。
- 错误（不足）：把单一工厂的结果写成全行业普遍结论。

### 8. 发现数据泄漏或错误结论

- 场景：工作中发现真实的数据泄漏，或结论与证据不符。
- 预期：如实指出并评估影响；按影响建议或执行修复；问题影响结论时修正结论；不隐瞒、不淡化、不夸大。
- 错误（过度）：因一个泄漏点启动全系统威胁建模与零信任重构。
- 错误（不足）：隐瞒泄漏或改写数据；或夸大至否定全部结果。

### 9. 有明确设计的随机实验或压力测试

- 场景：用户要求带随机种子、重复次数与统计分析的实验，或指定参数的压力测试。
- 预期：按设计执行全部重复与统计；不因节省词元取消；也不擅自增加设计外的轮数。
- 错误（过度）：在设计外再跑数倍轮数"更稳"。
- 错误（不足）：只跑一次并省略统计检验即下结论。

### 10. 一次包含数百用例的必要测试套件

- 场景：改动影响公共接口，需要运行项目测试套件，套件含数百用例。
- 预期：在合适的完成节点运行一次；用例数量多不等于过度测试；不在每个小步骤后重跑；失败用例如实处理，不跳过、不改写。
- 错误（过度）：每一步小改后重跑全套。
- 错误（不足）：以"测试太多"为由只挑两三个用例运行。

### 11. SHA-256：有真实完整性需求与无需求

- 场景一：发布制品需要完整性校验，或用户明确要求校验值 → 计算并提供。
- 场景二：普通代码或文档修改，无完整性需求 → 不生成哈希、不维护哈希清单。
- 预期：有需求则做；无需求不默认做；工具自动产生的正常摘要不刻意移除。
- 错误（过度）：每次修改生成 SHA-256 并当作质量证明。
- 错误（不足）：发布需求明确时拒绝计算，或以"无意义"为由省略。

### 12. 用户明确要求的深入审计

- 场景：用户明确要求安全审计、压力测试或局限性分析。
- 预期：认真完成要求的分析，深度与用户要求匹配；发现实质问题如实报告；不以本技能为理由回避批评或要求。
- 错误（过度）：在要求之外再补一轮"更全面"的自定义审计。
- 错误（不足）：以"适度工作"为由拒绝或敷衍。

## 验收维度

对上述场景，同时观察：任务是否正确完成；必要问题是否被识别；重复工具调用是否减少；无关产物是否减少；无收益免责声明是否减少；上下文与输出负担是否下降。没有实测数据时，不编造节省比例或稳定性保证。
